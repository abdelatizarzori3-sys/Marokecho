# قاعدة الأسئلة الشائعة المخصصة (برو)

تتيح هذه الميزة لصاحب حساب برو ذي استحقاق صالح أن يرفع JSON مراجعاً من أسئلة مؤسسته، ثم يصدّره لاحقاً. تُخزَّن الوثيقة الخاصة بالحساب على الخادم فقط؛ لا يوجد رابط ملف عام، ولا تعتمد الميزة على `localStorage` أو ترويسة عميل أو زر واجهة لإثبات الاشتراك.

## الصيغة المقبولة

```json
{
  "version": 1,
  "entries": [
    {
      "id": "working-hours",
      "question": "ما هي ساعات العمل؟",
      "answer": "نستقبل الاستفسارات من الأحد إلى الخميس، 9 صباحاً إلى 5 مساءً.",
      "keywords": ["ساعات العمل", "مواعيد الدوام"]
    }
  ]
}
```

لا تقبل الواجهة حقولاً إضافية. يدمج الاستيراد السجلات حسب `id`: يضيف المعرف الجديد، ويستبدل المعرف الموجود بعد التحقق الكامل. صيغة التصدير هي الصيغة نفسها، بلا معرف حساب أو مسار تخزين أو أسرار.

## الحدود والتحقق

- JSON واحد بحجم أقصاه 65,536 بايت، و100 سجل كحد أقصى.
- `id` من 1 إلى 64 حرفاً من الإنجليزية والأرقام و`-` و`_`.
- السؤال حتى 240 حرفاً، والجواب حتى 2,000 حرف، وحتى 8 كلمات مفتاحية لا تزيد كل منها على 64 حرفاً.
- تُوحَّد نهايات الأسطر إلى LF، وترفض محارف التحكم والحقول المكررة أو الفارغة أو غير المتوقعة.
- المطابقة نصية ومحلية وحتمية للسؤال أو الكلمات المفتاحية؛ لا تُنفَّذ حقول JSON ولا شيفرة منها، ولا يستدعي المسار LLM أو خدمة خارجية.
- تعرض الواجهة الردود بـ`textContent`، لذلك لا يُفسَّر نص الإجابة كـHTML.

## حد الاستحقاق قبل الإطلاق

المحرك الجديد **مغلق افتراضياً**. يلزم ربط `app.config["ENTITLEMENT_VERIFIER"]` في الخادم بتطبيق المصادقة ومخزن الاشتراكات الدائم. يجب أن يوفر الكائن التابع `verify(request)` قرار `EntitlementDecision` موثقاً يضم:

- `state="active"`؛
- `account_id` لهوية الحساب؛
- `subscription_id` من مزود الاشتراك؛
- `expires_at` بمنطقة زمنية وتاريخ مستقبليين.

تُرفض حالات الإلغاء والانتهاء وغياب الاستحقاق، وتبقى حالة الإعداد الناقص `purchase_configuration_required` بدلاً من تفعيل يدوي أو نجاح شراء صوري. يتطلب ربط الإنتاج اختيار مزود الدفع وبلد التحصيل وقناة Android، مع تحقق خادمي من أحداث الدفع القابلة لإعادة التسليم وربطها بالحساب قبل عرض الميزة كاشتراك قابل للشراء.
